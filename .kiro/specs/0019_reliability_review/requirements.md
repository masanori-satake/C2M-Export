# Requirements: 信頼性レビュー（spec 0019）

## 背景

Phase 1〜4（spec 0011〜0014）とスキル改善（spec 0015〜0018）を短期間に連続で追加した。機能追加の速度に対して、追加した仕組みの「壊れ方」の確認が追いついていない可能性がある。本 spec は新規機能の追加ではなく、既存実装の信頼性確認と、確認で見つかった問題の最小修正を扱う。

## レビュー観点

- V1 非同期ジョブ: stale 判定の妥当性、cancel と完了の競合、job_id の衝突、古いジョブ記録の蓄積、result 要約の正確さ。
- V2 チェックポイント再開: 再開時に起点・パラメータの同一性が担保されるか、破損行がある状態での再開の正しさ。
- V3 先読み（子孫一括取得）: フォールバック条件の網羅、上限超過時の切り捨て、循環・重複でのページ集合の同一性。
- V4 並列収集: 結果順序の直列時との同一性、中断時の future の扱い、スレッドローカルセッションの後始末。
- V5 見積もり: 対象0件・権限なし・起点解決失敗など境界ケースでの推定値と表示。
- V6 テストの質: モックで実経路を通っていない箇所、繰り返し実行での安定性（フレーク）。
- V7 秘密情報: ジョブ記録・worker.log・チェックポイント・結果ファイルにトークンが混入しないか。

## 進め方と完了条件

- 観点ごとに「実装とテストで確認した事実」を記録する。問題がなければ根拠を残して完了とする。
- 問題が見つかった場合は、再現方法を特定したうえで最小限の修正と回帰テストを同じ PR に入れる。
- 仕様変更にあたるもの（挙動の意図的な変更）は修正に含めず、別途提案として切り出す。
