# Requirements: 子孫数取得の失敗可視化とタイムアウト延長（spec 0021）

## 背景

2026-11-06、社内プロキシ経由の実機利用で「子孫数取得に多数回失敗した」との報告があった。コード確認（診断メモ）の結果、次の問題が判明した。

- 全体把握フェーズでは、ルートページごとの子孫数取得の失敗が警告ログにしか残らず、`unavailable_apis` に記録されない。1 件でも成功すればプレビュー件数がそのまま公開されるため、欠けた件数が確かな数字として報告されうる。
- 見積もりでは失敗した起点が `count_failed_root_page_ids` に記録されるものの、失敗起点は子孫数 0 として数えられるため、`is_large` 判定が過小に出ても機械可読な印がない（notes の文章のみ）。
- 子孫数取得はサーバ側で再帰的に数える重いエンドポイントで、大きなツリーでは読み取りタイムアウト（既定 30 秒）を超えやすいが、このエンドポイントだけタイムアウトを延ばす手段がない。

本 spec は、失敗の可視化 2 点と、原因がタイムアウトだった場合に使える延長手段 1 点を扱う。収集結果そのもの（ページ集合・分析内容）は変更しない。

## 要件

- R1 全体把握の部分失敗の可視化: Space 内で子孫数取得に失敗したルートページがある場合、その事実が `unavailable_apis` と Space 単位の出力に残ること。失敗が 0 件のときの出力は従来と同一であること。
- R2 見積もりの過小評価の明示: `count_failed_root_page_ids` が空でないとき、見積もり結果に「過小評価の可能性あり」を示す機械可読フラグが立つこと。失敗がないときはフラグが立たないこと。
- R3 子孫数取得専用の読み取りタイムアウト: 子孫数取得エンドポイントだけ読み取りタイムアウトを延長できる設定（CLI / YAML）を追加すること。未指定時は従来動作（全体の読み取りタイムアウト）と同一であること。他エンドポイントのタイムアウトには影響しないこと。

## 完了条件

- R1〜R3 それぞれに回帰テストがあり、全テストが通過する。
- 失敗 0 件のケースで、全体把握・見積もりの出力が従来と変わらないことをテストで固定する。
- README.md / README_DEV.md とスキル文書（options.md / output_schema.md / SKILL.md）を実装に合わせて更新し、正本と複製先が同期している。
