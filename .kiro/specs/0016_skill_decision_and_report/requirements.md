# Requirements: スキルの実行決定表と結果報告テンプレート（spec 0016）

## 背景

spec 0015 で SKILL.md を references 分離し、本体は 3,692 トークンになった。手順の骨格（見積もり→大きければ非同期）はあるが、同期 / 非同期 / 分割の選択基準と、結果の報告形式はエージェントの裁量が大きく、実行ごとにばらつく。スキル UX 改善の第2弾として、判断と報告の型を本体に明記する。

## 要件

### 1. 実行の決定表
- 1.1 見積もり結果（`is_large`、`exceeds_skill_default_timeout`、見積もり失敗）から実行方法（同期実行 / 上限延長 / 非同期 / 進めない）を機械的に決められる表を、見積もりの読み方の直後に置く。
- 1.2 既存の文章ルール（`is_large` のとき自動で対象を絞らない、非同期実行の手順）と矛盾しないこと。

### 2. 結果報告の型
- 2.1 報告の順序（結論 → 主要数値 → 不確実性 → 次のアクション）を「結果の読み方」の直後に明記する。
- 2.2 報告ルール（`partial` を「完了」と表現しない、取得失敗・未取得は uncertainties から必ず含める）を明記する。

### 3. 配置と上限
- 3.1 どちらも毎回の実行で使うため references ではなく本体に置く。
- 3.2 追加後の本体は 5,000 トークン未満（SkillMap-Solo R5 既定上限）を維持する。現行 3,692 トークン、追加見込み約 650 トークン。
- 3.3 コードの変更はしない。3 箇所の複製同期を行う。
