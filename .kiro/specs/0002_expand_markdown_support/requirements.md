# 要件定義: Markdown 変換対応表現の拡充

## 概要

Confluence Storage Format (XHTML) から Markdown への変換において、現在サポートしていない、
または変換が不完全な表現を拡充する。目的は **AI ナレッジベースとしての利用** であり、
綺麗なレンダリングよりも **元ページの情報を余さず Markdown に残すこと** を最優先とする。

## 背景・方針

### 設計原則: 情報の非欠損を最優先

- 本ツールの出力は人間の閲覧用ではなく、LLM への入力（RAG 等）を主用途とする。
- したがって「見た目の再現」よりも「テキスト情報がすべて残ること」を優先する。
- Markdown 標準構文で表現できない要素も、近似表現やプレーンテキスト化によって
  情報自体は必ず残す。

### ページリンクの扱い方針（重要）

- ページ間リンクは「ジャンプ用の導線」としてではなく、
  「参照対象の名前（ページタイトル）が本文テキストに残ること」を価値とみなす。
- リンクは `[ページタイトル](Confluence 絶対 URL)` の形式で残す。
- **ファイル内アンカー解決や、分割ファイル間の相対パス解決は行わない。**
  - 理由: DFS 統合・Zip 分割・サイズ制限により「どのページがどのファイルのどこに入るか」が
    実行時に変動し、リンク解決先が不安定になるため。
  - AI 利用では対象タイトルがテキストとして残れば十分で、Confluence 絶対 URL により
    人間による原典参照（トレーサビリティ）も確保できる。
- この方針は README にも明記し、利用者へ「ナレッジとしての利用を最優先する」考え方とともに伝える。

## 用語

- **Storage Format**: Confluence がページ本文を保持する XHTML 形式。
- **still-supported / 素直な還元**: Markdown 標準または GFM で自然に表現できる変換。
- **近似還元**: Markdown に専用構文がなく、テキスト化・簡易装飾で情報のみ残す変換。

## 要件

### 要件 1: thead/tbody を含む表の変換（Must）

**ユーザーストーリー:** 利用者として、`<thead>`/`<tbody>` で囲まれた Confluence の表が
Markdown に正しく出力されてほしい。表が丸ごと消えることを防ぎたい。

#### 受け入れ基準

1. WHEN 表が `<thead>`/`<tbody>` で行をラップしている THEN システムは全ての `tr` を検出して Markdown 表に変換する SHALL。
2. WHEN 表が `thead`/`tbody` を持たず `tr` を直下に持つ THEN システムは従来通り変換する SHALL（後方互換）。
3. WHEN `<thead>` に行が存在する THEN システムはその行をヘッダー行として扱う SHALL。
4. WHEN `<thead>` が存在せず `<th>` を含む行が先頭にある THEN システムはその行をヘッダー行として扱う SHALL。

### 要件 2: 引用（blockquote）

**ユーザーストーリー:** 利用者として、引用ブロックが Markdown の引用として残ってほしい。

#### 受け入れ基準

1. WHEN `<blockquote>` を検出する THEN システムは各行の先頭に `> ` を付与して変換する SHALL。
2. WHEN 引用内に複数段落や改行がある THEN システムは各行に `> ` を付与する SHALL。

### 要件 3: 水平線（hr）

#### 受け入れ基準

1. WHEN `<hr>` を検出する THEN システムは `---` を出力する SHALL。

### 要件 4: 打ち消し線（del/s/strike）

#### 受け入れ基準

1. WHEN `<del>`, `<s>`, `<strike>` を検出する THEN システムは `~~テキスト~~` に変換する SHALL。

### 要件 5: ネストリストのインデント

**ユーザーストーリー:** 利用者として、多階層の箇条書き/番号リストの階層構造が保たれてほしい。

#### 受け入れ基準

1. WHEN リストがネストしている THEN システムは階層の深さに応じたインデント（半角スペース）を付与する SHALL。
2. WHEN 番号付きリストがネストしている THEN システムは階層を保った上で項目を出力する SHALL。
3. WHEN リスト項目内に子リストがある THEN システムは子リストを親項目の下にインデントして出力する SHALL。

### 要件 6: タスクリスト（チェックボックス）

**ユーザーストーリー:** 利用者として、Confluence のタスクリストがチェック状態付きで残ってほしい。

#### 受け入れ基準

1. WHEN 未完了タスク（`ac:task` の status が incomplete 等）を検出する THEN システムは `- [ ] 本文` を出力する SHALL。
2. WHEN 完了タスク（status が complete）を検出する THEN システムは `- [x] 本文` を出力する SHALL。

### 要件 7: 画像（img / ac:image）

**ユーザーストーリー:** 利用者として、ページ内の画像や添付画像の存在と参照名が Markdown に残ってほしい。

#### 受け入れ基準

1. WHEN `<img>` を検出する THEN システムは `![alt](src)` を出力する SHALL。相対 src は絶対 URL に正規化する。
2. WHEN `<ac:image>` 内に `<ri:attachment ri:filename="...">` がある THEN システムはファイル名を alt/参照として残す SHALL。
3. WHEN `<ac:image>` 内に `<ri:url ri:value="...">` がある THEN システムはその URL を参照として残す SHALL。
4. WHEN alt テキストが取得できない THEN システムは代替としてファイル名を alt に用いる SHALL。

### 要件 8: ページ間リンク（ac:link + ri:page）

**ユーザーストーリー:** 利用者として、他ページへのリンクが参照先タイトルとともに残ってほしい。

#### 受け入れ基準

1. WHEN `<ac:link>` 内に `<ri:page ri:content-title="...">` があり、かつ `ri:space-key` が判明する THEN
   システムは `[タイトル](絶対 URL)` を出力する SHALL（A案）。
2. WHEN `ri:space-key` が判明しない THEN システムはタイトルをテキストとして必ず残す SHALL
   （URL 無しのプレーンテキスト、または表示テキストのみ）。情報欠損を起こさない。
3. WHEN リンクの表示テキスト（`ac:link-body` / `ac:plain-text-link-body`）が別途指定されている THEN
   システムはそれを表示テキストとして優先する SHALL。
4. システムはファイル内アンカー解決・分割ファイル間の相対パス解決を行わ**ない** SHALL。

### 要件 9: pre 単体のコードブロック

#### 受け入れ基準

1. WHEN マクロ外の `<pre>` を検出する THEN システムは言語指定なしのコードブロック（```）で囲む SHALL。

### 要件 10: 定義リスト（dl/dt/dd）

#### 受け入れ基準

1. WHEN `<dl>`/`<dt>`/`<dd>` を検出する THEN システムは用語と説明を情報欠損なく出力する SHALL（例: `**用語**` + 説明行）。

### 要件 11: 近似還元（情報のみ残す）

**ユーザーストーリー:** 利用者として、Markdown に専用構文がない表現でも、テキスト情報が失われないでほしい。

#### 受け入れ基準

1. WHEN 下線（`<u>`）を検出する THEN システムはテキストを必ず残す SHALL。
2. WHEN 上付き（`<sup>`）/下付き（`<sub>`）を検出する THEN システムはテキストを必ず残す SHALL。
3. WHEN 絵文字（`<ac:emoticon>`）を検出する THEN システムは Unicode またはショートコードとして残す SHALL。
4. WHEN ユーザーメンション（`<ac:link>` + `<ri:user>`）を検出する THEN システムは `@ユーザー名` 等の識別可能なテキストで残す SHALL。
5. WHEN レイアウト（`<ac:layout>` / `<ac:layout-section>` / `<ac:layout-cell>`）を検出する THEN システムは段組みの見た目は捨てつつ、中身を縦積みでテキストとして残す SHALL。

### 要件 12: 表の複雑表現の近似

#### 受け入れ基準

1. WHEN セルに `colspan`/`rowspan` がある THEN システムは表を破綻させずに近似出力し、セル内テキストを残す SHALL。
2. WHEN セル内に表・箇条書き・改行がある THEN システムは表構造を破綻させずにテキストを残す SHALL（`<br>` 等で潰すことを許容）。

### 要件 13: 後方互換性

#### 受け入れ基準

1. WHEN 既存のテストを実行する THEN システムは全て成功する SHALL。
2. システムは既にサポート済みの表現（見出し・段落・太字・斜体・コード・既存マクロ等）の変換結果を退行させない SHALL。

### 要件 14: 堅牢性・エラー波及防止（誠実な部分成功）

**ユーザーストーリー:** 利用者として、一部のページデータが不完全でも処理全体が停止せず、
何が起きてどう対処したかが誠実にログ表示され、取得できた分の Markdown が必ず手に入ってほしい。
途中で黙って止まったり、情報が無言で欠損したりして、ツールへの信頼を損なわないでほしい。

#### 受け入れ基準

1. WHEN 変換対象の XHTML が不完全・破損している（閉じタグ欠落、途中で切れている等） THEN
   変換器は例外を送出せず、取得可能な範囲のテキストを含む Markdown を返す SHALL。
2. WHEN 個別要素（画像・リンク・表・マクロ等）で必要な属性が欠落している THEN
   変換器は例外を送出せず、その要素をスキップまたは近似変換しつつ、残りの本文を出力する SHALL。
3. WHEN DFS 巡回中の特定ページの取得または変換で例外が発生する THEN
   システムは当該ページをスキップし、後続ページの処理を継続する SHALL（処理全体を停止しない）。
4. WHEN ページをスキップする THEN システムは日本語のログで「現象・原因（例外詳細）・対処方法」を出力する SHALL。
5. WHEN 一部ページがスキップされても THEN システムは処理できたページを統合した Markdown を出力する SHALL（部分成功）。
6. WHEN スキップが発生した THEN システムは処理完了時に、成功ページ数・スキップページ数（および対象 ID）を
   サマリとして日本語ログに出力し、利用者が欠損の有無を把握できるようにする SHALL。
7. システムは、空 body（空文字）や取得結果の一部欠落に対しても例外を送出せず、
   可能な限りの出力を行う SHALL。

### 要件 15: コードブロックの構文汚染防止（フェンス動的伸長）

**ユーザーストーリー:** 利用者として、あるコードブロックの記法崩れが、同一ページの後続要素や
次のページの本文まで「コードとして」巻き込むことがないようにしてほしい。

#### 背景

Markdown のコードフェンス（```` ``` ````）は開閉ペアで閉じる。コードの中身に ```` ``` ```` が
含まれるとフェンスが途中で割れ、閉じフェンスが失われて後続テキストがコード扱いされる。
ページは統合時に単純連結されるため、1 ページの構文崩れが後続ページに侵食する。

#### 受け入れ基準

1. WHEN コード系マクロ（`code` / `noformat` / `plantuml` / 汎用 plain-text-body）の中身に
   バッククォート連続（```` ``` ```` 以上）が含まれる THEN システムは開閉フェンスを、
   中身に現れる最長連続バッククォートより長い長さに動的拡張する SHALL（CommonMark 準拠）。
2. WHEN フェンスを動的拡張する THEN システムは開きフェンスと閉じフェンスの長さを一致させ、
   コードブロックが確実に閉じる SHALL。
3. WHEN 複数ページを統合する THEN あるページのコードブロックが後続ページの本文を
   コードとして巻き込まない SHALL。
4. WHEN 入力 XHTML が途中で切れている（コードマクロが不完全） THEN
   システムは出力の開きフェンスと閉じフェンスをペアで揃える SHALL。

### 要件 16: ドキュメント更新

#### 受け入れ基準

1. WHEN 本機能を実装する THEN `README.md` にサポートする表現一覧と「ナレッジ利用最優先」の方針・ページリンク方針を追記する SHALL。
2. WHEN 本機能を実装する THEN `README_DEV.md` に変換ロジックの拡張内容を追記する SHALL。
