# 設計: Markdown 変換対応表現の拡充

## 1. 設計方針

### 1.1 全体像

本機能は `c2m_export/converter.py` の `MarkdownConverter` クラスに閉じて実装する。
`cli.py` / `confluence.py` / `config.py` への影響はない（変換ロジックのみの拡張）。

既存の再帰巡回構造（`convert` → `_walk` → `_process_tag`）を維持し、
`_process_tag` に分岐を追加、および表・マクロハンドラを拡張する。

### 1.2 情報非欠損の原則

- 未知タグは従来通り `_walk` で中身を再帰処理し、テキストを残す（既存挙動を踏襲）。
- Markdown に専用構文がない表現は、近似（テキスト化・簡易装飾）で必ずテキストを残す。
- 変換で情報を「消す」のは、ナビゲーション系マクロ（`toc` 等、AI ナレッジに不要）に限定する。

### 1.3 ネスト対応のための状態受け渡し

ネストリストのインデント制御のため、`_walk` / `_process_tag` に
`list_depth`（リストのネスト深さ、デフォルト 0）を引き回す。
既存の `level`（見出しレベルシフト用）と併存させる。

- 後方互換のためデフォルト引数を付与し、既存呼び出し（`self._walk(tag, level)`）は影響を受けない。
- シグネチャ変更方針: `_walk(node, level, list_depth=0)`, `_process_tag(tag, level, list_depth=0)`。

## 2. コンポーネント設計

### 2.1 `_process_tag` への追加分岐

処理順は「特異なもの → 汎用」の順。既存分岐の前後関係を壊さないよう挿入する。

| タグ | 追加/変更 | 変換 |
|---|---|---|
| `blockquote` | 追加 | 各行に `> ` を付与 |
| `hr` | 追加 | `\n---\n` |
| `del` / `s` / `strike` | 追加 | `~~...~~` |
| `u` | 追加 | テキストのみ（装飾なし） |
| `sup` / `sub` | 追加 | テキストのみ |
| `img` | 追加 | `![alt](src)`、相対 src は絶対 URL 化 |
| `pre` | 追加 | 親がコードマクロ由来でない単体 pre を ``` で囲む |
| `dl` / `dt` / `dd` | 追加 | `**用語**` + 説明行 |
| `ul` / `ol` | 変更 | `list_depth` を +1 して子を処理 |
| `li` | 変更 | `list_depth` に応じたインデント付与、子リストを内包処理 |
| `ac:image` | 追加（マクロ判定前に処理） | `ri:attachment` / `ri:url` から参照名/URL を抽出 |
| `ac:link` | 追加 | `ri:page` / `ri:user` / `ri:attachment` を判定して変換 |
| `ac:emoticon` | 追加 | `ac:emoji-fallback` 属性 or shortname を残す |
| `ac:layout*` | 追加（実質は再帰） | 縦積み。セクション間に空行を入れる程度 |
| `ac:task-list` / `ac:task` | 追加 | チェックボックスリスト化 |

### 2.2 表変換の再設計（要件1・12）

`_handle_table` を次のように再設計する。

#### 行の収集

現状の `table.find_all('tr', recursive=False)` は `thead`/`tbody` を挟むと 0 件になる。
これを、`thead` / `tbody` / `tfoot` を考慮した収集に変更する。

- ヘッダー行の決定順:
  1. `<thead>` 内の `tr` があればそれをヘッダー行とする。
  2. なければ `<tbody>`（または table 直下）の先頭行を候補とし、
     その行が `<th>` を含むならヘッダー行、含まなければ「ヘッダーなし」とする。
- ボディ行: ヘッダー行を除いた全 `tr`（`tbody` / `tfoot` / 直下を連結）。

行探索は「table 配下の tr を、thead→tbody→tfoot→直下 の順で、
それぞれ直下の tr を拾う」方針にする。ネストした表の tr を誤って親に取り込まないよう、
各セクションコンテナの**直下**の `tr` のみを対象にする。

#### ヘッダーなし表の扱い（要件1-4 / 情報非欠損）

Markdown 表はヘッダー行が必須（区切り線が要る）。ヘッダーが特定できない場合は、
情報欠損を防ぐため **空ヘッダー行** を生成して区切り線を置く。

```
|  |  |
| --- | --- |
| D1 | D2 |
```

#### セル内容（要件12）

- セル内は従来通り `_walk` した結果を `.strip()` し、改行を `<br>` に置換する。
- セル内テキストの `|` は表を破綻させるため `\|` にエスケープする（新規対応）。
- `colspan` は「値を複製 or 空セルで列数を合わせる」。実装は空セル補完を基本とし、
  少なくとも列数の整合を保って表が破綻しないことを優先する。
- `rowspan` は Markdown で表現不可のため、当該セルのテキストは出現行にのみ残す（近似）。

### 2.3 リストのインデント設計（要件5）

- `_process_tag` で `ul`/`ol` を検出したら、子 `li` を `list_depth+1` で処理する。
- `li` の出力は `"  " * (list_depth-1)` 相当のインデント + マーカー（`- ` or `1. `）+ 本文。
- `li` 内に子 `ul`/`ol` がある場合、本文と子リストを分離して、子リストは次行以降にインデント出力する。
  - 実装方針: `li` の直下テキスト/インライン要素をまず処理し、その後に子リストを `_process_tag` で処理して連結。

### 2.4 リンク/画像の URL 正規化

既存の `<a>` 同様、`href`/`src` が `/` 始まりなら `self.base_url + href` で絶対化する。
`ac:link` の `ri:page` からはタイトルは取れるが URL は取れないため、
Confluence の表示 URL を組み立てる。

**採用方針: A案（情報欠損なし・変換器のインターフェース変更なし）**

- URL 構築: `ri:page` が `ri:space-key` を持つ場合のみ、Data Center の遷移 URL
  `{base_url}/display/{SPACEKEY}/{Title を URL エンコード}` を組み立て、`[タイトル](URL)` を出力する。
- `ri:space-key` が無い場合は、URL を組み立てず **タイトルをテキストとして残す**
  （表示テキストがあればそれ、無ければタイトル文字列）。
  - 理由: 変換器はページのスペース情報を持たず、同一スペース内リンクではスペースキーが省略されがち。
    誤った URL を作るより、確実にタイトルを残す方が AI ナレッジ用途に適う。
- いずれの場合も **最低限タイトルは必ずテキストとして残す**（情報非欠損）。

> 補足: この URL はあくまで人間参照用のトレーサビリティ。AI ナレッジ的価値はタイトル文字列にある
> （requirements の方針どおり、ファイル内解決は行わない）。

### 2.5 コードフェンスの動的伸長（要件15）

コードブロックを生成する箇所は現在 2 つ（`_handle_macro` の legacy code/noformat、
`_handle_structured_macro` の plain-text-body）。ここを **共通ヘルパー** に集約する。

```python
def _wrap_code_block(self, content: str, lang: str = "") -> str:
    """
    コード文字列をフェンスで囲む。中身に含まれる最長の連続バッククォートより
    1 つ以上長いフェンスを用いることで、フェンスが途中で割れて後続を巻き込むのを防ぐ
    （CommonMark 準拠）。開きと閉じのフェンス長は必ず一致させる。
    """
    # 中身に現れる連続バッククォートの最長を求める
    longest = 0
    for m in re.finditer(r"`+", content):
        longest = max(longest, len(m.group(0)))
    fence_len = max(3, longest + 1)
    fence = "`" * fence_len
    return f"\n{fence}{lang}\n{content}\n{fence}\n"
```

- `code` / `noformat` / `plantuml` / 汎用 plain-text-body / pre 単体（要件9）は
  すべてこのヘルパー経由でフェンスを生成する。
- 開き・閉じの長さは同一変数から生成するため必ず一致する（受け入れ基準 15-2, 15-4 を満たす）。
- 途中で切れた入力でも、`get_text()` で得た中身をこのヘルパーに通すため、
  開閉フェンスはペアで揃う。

### 2.6 タスクリスト（要件6）

Confluence Storage Format のタスクは概ね次の構造:

```xml
<ac:task-list>
  <ac:task>
    <ac:task-status>complete</ac:task-status>
    <ac:task-body>本文</ac:task-body>
  </ac:task>
</ac:task-list>
```

- `ac:task-status` が `complete` → `- [x] `、それ以外 → `- [ ] `。
- `ac:task-body` を `_walk` して本文を得る。

## 3. エラー処理・エッジケース・堅牢性（要件14）

### 3.1 変換器レベルの堅牢性

設計原則: **変換器は例外を外に伝播させない。取れる情報は必ず残す。**

- 空の表（行 0 件）: 従来通り空文字を返す。
- 属性欠落（alt なし・title なし・src なし・ri:page/ri:user なし等）:
  代替値（ファイル名等）を用い、無ければ当該要素をスキップしつつ本文は残す。例外は投げない。
- 不完全・破損 XHTML（閉じタグ欠落、途中で切れている）:
  `BeautifulSoup("html.parser")` の寛容パースに委ね、部分的な DOM から取れるテキストを返す。
- 想定外のマクロ/タグ: 既存フォールバック（`_walk` で再帰）に委ね、テキストは残す。
- セル内の `|` / 改行 / ネスト表: 2.2 の方針でエスケープ・`<br>` 置換して破綻を防ぐ。
- 個別ハンドラ（表・画像・リンク・タスク・マクロ）内で想定外の構造に遭遇しても、
  `try/except` で握って空または近似結果を返し、変換全体を止めない方針とする
  （握った場合は `logger.warning` で「現象・原因・対処方法」を日本語出力）。

### 3.2 CLI レベルの波及防止（既存挙動の維持・強化）

`export_tree` は既に個別ページの例外を `try/except ... continue` で捕捉し、後続ページを継続する。
本 spec ではこの挙動を **回帰テストで保証** し、さらに以下を追加する。

- スキップされたページ ID を集計する（`skipped_pages` リスト等）。
- 処理完了時に **サマリログ** を日本語で出力する:
  - 成功ページ数、スキップページ数、スキップした page_id 一覧。
  - 例: 「エクスポート完了（現象）。成功 12 ページ / スキップ 1 ページ（page_id=xxxx）（原因: 上記ログ参照）。
    スキップされたページは元の Confluence で内容と権限を確認してください（対処方法）」
- 部分成功でも `processed_md` を返し、`main()` は取得できた分を書き出す（既存どおり）。

> 注: `export_tree` の戻り値にスキップ情報を含める小さなインターフェース拡張を行う。
> 既存の戻り値 `(md, total_bytes, page_count)` に `skipped_page_ids` を追加するか、
> ログ出力のみに留めるかは実装時に判断（テスト容易性の観点からは戻り値に含める方が望ましい）。

### 4.2 堅牢性・波及防止テスト（要件14）

新規 `tests/test_robustness.py`（または既存テストへの追加）で以下を検証する。

#### 変換器レベル（例外を投げず情報を残す）

- 不完全 XHTML（閉じタグ欠落・途中で切れた表）を渡しても例外を送出せず、部分テキストを返す。
- `ac:image` に `ri:attachment`/`ri:url` が無い、`ac:link` に `ri:page`/`ri:user` が無い、
  `img` に `src` が無い場合でも例外なく、周辺本文が残る。
- 空 body（`""`）で空文字を返す。
- 列数不揃いの表・`thead` のみで `tbody` 空の表でも例外を投げない。

#### コードフェンスの構文汚染防止（要件15）— 対策1が確実に機能することの検証

- コード系マクロの中身に ```` ``` ```` を含めたとき、出力の開き/閉じフェンスが 4 連以上に伸長され、
  かつ開きと閉じの長さが一致する。
- 中身に ```` ```` ````（4連）を含む場合、フェンスが 5 連以上になる（最長連続+1 のロジック検証）。
- 通常のコード（バッククォートを含まない）では従来どおり 3 連フェンスになる（退行防止）。
- **ページ連結の波及テスト**: 「未閉じになりやすいコードを含むページ」＋「通常の本文ページ」を
  `export_tree` で連結し、2 ページ目の本文が 1 ページ目のコードブロックに飲み込まれていないことを、
  出力全体のフェンス開閉数が偶数（＝全コードブロックが閉じている）であることで検証する。
- `pre` 単体（要件9）も同じヘルパー経由でフェンスが伸長されることを確認。

#### CLI レベル（後続ページに波及しない・部分成功・誠実なログ）

`ConfluenceClient` をスタブ化して `export_tree` を直接テストする。

- 3 ページのツリーで、2 ページ目の `get_page`（または `get_child_pages` / `convert`）が例外を投げるよう仕込む。
  - 検証: 例外が `export_tree` の外に漏れない。
  - 検証: 1・3 ページ目の内容が戻り値 Markdown に含まれる（部分成功）。
  - 検証: `page_count` が成功数と一致する。
  - 検証: スキップ情報（戻り値 or ログ）にスキップされた page_id が含まれる。
- ログ検証（`caplog`）: スキップ時に「現象・原因・対処方法」を含む日本語エラーログが出る。
- サマリログ検証: 完了時に成功数・スキップ数・スキップ page_id を含むサマリが出る。

> スタブ方針: `client` は `get_page` / `get_child_pages` / `base_url` を持つ軽量スタブクラスで代替する。
> `converter` は実物、または特定ページで例外を投げるモックを用いる。
